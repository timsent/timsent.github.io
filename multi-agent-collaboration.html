Multi-Agent Collaboration

Building towards our multi-agentic future

Tim Sent · Director, Architecture · September 2026

The path from function calling to Agent2Agent, in the order the field actually built it: OpenAI's tool calling, LangChain's standardized interface, Mixture of Agents and the multi-agent frameworks that followed, Anthropic's Model Context Protocol, and Google's Agent2Agent Protocol. The goal is to explain the innovations that led to A2A, and how MCP and A2A work together rather than in competition.

From Text to Action

Tool calling gave LLMs a way to act

Before tool calling, a large language model could only generate text drawn from its training data. Asked to book a flight, it could describe how to do so, but it had no way to check real availability, no way to take action, and no way to look anything up externally.

Before Tool Calling

A model could understand intent and simulate a plausible answer, but it could not access real-time data, interact with a booking system, or confirm anything against the outside world. Every answer was a guess dressed up as an explanation.

After Tool Calling

OpenAI introduced tool calling in June 2023 with GPT-3.5-turbo and GPT-4. Developers define tools by name, description, and a JSON schema for their arguments; the model decides when a request matches a tool, and outputs a structured call for the application to execute.

The get_weather example

A user asks "What's the weather like in Paris today?" The application and the model exchange five messages to answer it:

  1. The application sends the user's message to the model, along with a definition of the available functions.
  2. The model decides to invoke get_weather with the appropriate arguments.
  3. The application parses the call and executes the function, requesting the current weather for Paris from an external API.
  4. The weather API responds, and the application formats the result as a message from the tool.
  5. The application sends that result back to the model, which crafts a final, user-friendly response.

The tool calling sequence for a single request: the application defines the tool and forwards the message, the model calls the tool, the application executes it and returns the result, and the model turns that result into a final response.

Standardizing tool calling

Between June 2023 and September 2024, OpenAI, Anthropic, Google DeepMind, Cohere, and Meta all introduced tool calling into their models, each with its own interface. What was missing was a standard. LangChain closed that gap in April 2024 with a consistent interface for binding tools to any model that supports tool calling, defined once with a name, a description, and a JSON schema, and reused across providers.

Multi-Agent Frameworks

From one tool call to many agents

Mixture of Experts activates only the most relevant parts of a single large model for a given input, keeping inference cost down as model scale grows. Mixture of Agents applies that same idea across whole models: proposer agents generate candidate responses, and aggregator agents review and refine them into a single, higher quality answer, without any additional training.

Mixture of Experts (MoE)

Mixture of Experts is a neural network architecture that improves the efficiency and scalability of large neural networks by activating only a subset of the model's components, called experts, for each input. Instead of activating the entire model, only the most relevant experts are used, which reduces computation while maintaining or improving performance, and lets a model scale to billions or trillions of parameters without a linear increase in inference cost.

Sparse Mixture of Experts with Top-1 gating: a small gate network scores every expert for the input, and only the highest scoring expert, FFN2 here at p=0.76, actually processes it. The other three stay idle for this input, which is what keeps inference cost from growing with the number of experts.

The sparse activation encourages expert specialization, so the network handles diverse tasks more effectively, and separating training-time compute from inference-time compute lets large models run efficiently in deployment without losing their capacity to learn complex patterns. A 2025 survey catalogs five further ways to route inputs to experts: BASE Layers, domain mapping with random gating, expert-choice gating, attention routing, and soft MoE, which merges experts instead of selecting one.

A Survey on Mixture of Experts in Large Language Models — arXiv:2407.06204

Mixture of Agents (MoA)

Mixture of Agents, described in Wang et al.'s "Mixture-of-Agents Enhances Large Language Model Capabilities," applies the same idea across whole models rather than components within one. It is built as a layered system, where each layer holds several Proposer and Aggregator agents, and each layer takes the output from the previous one and improves upon it.

Each layer's agents take every prior layer's output as input. Proposers generate candidate responses; aggregators review those candidates and produce a refined response, potentially combining or rephrasing them, until the final layer's single aggregator produces the answer.

This architecture encourages modular composition: agents can be heterogeneous, different model sizes or architectures, and configured dynamically. It improves language model performance through structured collaboration between specialized agents, offering better quality, flexibility, and efficiency without additional training.

Other multi-agent frameworks

LangChain and LangGraph have evolved to better support multi-agent systems, while CrewAI and MetaGPT build around the roles each agent takes on in the network.

The dominant multi-agent design pattern follows the mixture-of-agents model: layered agents that build on and refine each other's output.

Model Context Protocol

A standard way for models to reach the world

Anthropic introduced the Model Context Protocol (MCP) in November 2024 to standardize how AI models interact with external tools, resources, and applications. Before MCP, integrations were custom and inconsistent, requiring teams to rewrite the same logic for every model, platform, or vendor. MCP is a foundational layer for modular, multi-agent, tool-augmented AI systems, often described as the USB-C of AI apps.

Interoperability

Models, tools, and applications can all speak a shared language.

Composability

Tools, workflows, and agents are easy to plug in.

Separation of Concerns

Model behavior, tool logic, and application logic stay modular.

Scalability

One integration supports many AI models and use cases.

Tools are model-controlled functions the model can invoke. Resources are application-controlled data, files, database records, API responses, exposed to the model. Prompts are user-controlled templates for common requests.

01

For AI Application Developers

  • Plug-and-play integration: connect an app to any MCP server with no extra work
  • Universal compatibility: one interface across providers, no per-deployment refactor
02

For Tool or API Developers

  • Build once, use everywhere: one integration exposed to every MCP-compatible application
  • Standardized interfaces make a tool predictable to invoke across models and platforms
03

For End Users

  • Smarter, more capable apps that understand context, reference documents, and take real action
  • A more consistent experience across different AI products
04

For AI Product Teams

  • Defined roles between application logic, tool logic, and AI reasoning
  • Frontend, model, and backend teams can work in parallel on a shared standard

An ecosystem forming quickly

Salesforce, SAP, Slack, GitHub, Google Drive, and dozens of other platforms now expose MCP servers, alongside thousands of community servers listed across marketplaces including MCP.so, Smithery.ai, Glama, Cursor Directory, Mastra.ai, and Portkey.ai. Clients include Claude.ai, the Claude Desktop app, Amazon Q, Windsurf, Cursor, and Microsoft Copilot Studio.

Agent2Agent Protocol

Agents talking to agents, not just tools

Google introduced the Agent2Agent (A2A) Protocol in April 2025 as an open standard for communication between AI agents built on different frameworks and by different vendors. Where MCP connects a model to tools and data, A2A lets independent, opaque agents, each with their own roles, capabilities, and tools, coordinate toward a shared goal without a human in the loop at every step.

What A2A standardizes

  • A common transport: JSON-RPC 2.0 over HTTP(S)
  • Discovery through Agent Cards, so agents can advertise capabilities and be found
  • Task management for long-running, multi-turn collaborative work
  • Support for text, files, structured data, and other rich media
  • Security and asynchronicity as first-class design concerns

Key design principles

  • Simplicity — reuse HTTP, JSON-RPC, and Server-Sent Events rather than new standards
  • Enterprise readiness — authentication, authorization, privacy, tracing, monitoring
  • Asynchronous first — long-running tasks and streaming, not just request and reply
  • Modality agnostic — text, audio, video, and structured data alike
  • Opaque execution — agents collaborate without exposing internal logic or tools

A future where agents represent you

Today's most advanced demos still have a person talking directly to an enterprise's agent. A2A points toward a future where consumers have their own agent acting as the go-between, one that can compare several companies' agents and negotiate the best outcome on the person's behalf, exactly the kind of agent-to-agent negotiation A2A is built to carry.

Netting It Out

MCP and A2A are complementary, not competing

MCP standardizes how a model accesses tools, data, and dynamic context. A2A standardizes how independent agents communicate, discover each other, and collaborate. In simple terms, MCP is about model-to-resource interaction, and A2A is about agent-to-agent communication. Most agentic systems will need both.
